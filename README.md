# ComfyUI-xingz · ComfyUI 图像信息 / 图像规范

读取图片的尺寸与比例，直接驱动原生「分辨率选择器」；顺手把任意尺寸对齐到模型合法的倍数。纯 Python，无第三方依赖。

| 节点 | 类型 | 一句话 |
|---|---|---|
| 图像信息 | `ImageAspectRatio` | 输入图像 → 宽度 / 高度 / 宽高比 / 百万像素 / 分辨率文本 |
| 图像规范 | `NormalizeImage` | 输入图像 + 对齐倍数 → 合法尺寸的图 / 宽度 / 高度 / 参考分辨率 |

要求 ComfyUI 0.39+（V3 节点 API）。节点在「图像/分析」分类下。

## 它解决什么问题

ComfyUI 原生「分辨率选择器」只能手动选比例、手动填百万像素——它读不到你的输入图；「空 Latent 图像」也要手填宽高。所以图生图时经常是这几件事在折腾人：

| 遇到的问题 | 以前怎么做 | 用这组节点 |
|---|---|---|
| 想按原图比例出图，却不知道原图多大、比例多少 | 看文件属性、心算比例、再挑下拉 | 「图像信息」的宽高比 + 百万像素直接连「分辨率选择器」 |
| 出图比例差一点，人物被拉长 / 构图被改 | 反复试尺寸 | 同上：自动按原图比例和原图像素量还原尺寸 |
| 600×899 这种尺寸喂 Qwen / Flux 报错、或被悄悄改尺寸 | 手算 8 / 16 / 32 的倍数 | 「图像规范」（倍数 32）→ 608×896 |
| Qwen 图生图的「分辨率」不知道填多少 | 靠猜、靠试 | 「图像规范」→ 参考分辨率，直接连过去 |
| 保存的图想带上尺寸信息 | 手动改名 | 「图像信息」→ 分辨率 → 保存图像的 filename_prefix |

## 什么时候用

- **图生图 / 换装 / 局部改图**：想保住原图的构图比例，用「图像信息」驱动分辨率选择器。
- **喂对尺寸挑剔的模型**：Qwen-Image 要 32 对齐、Flux 16、SDXL 8，先用「图像规范」规范化。
- **批量处理尺寸不一的图**：每张图各自规范化，不用一套套手改。
- **Qwen 图像 2.1 图生图**：把「图像规范」的参考分辨率接到它的分辨率输入。
- **只是想知道 / 展示尺寸**：用「图像信息」的分辨率文本。

反过来，这些情况不需要它：固定尺寸出图（直接用空 Latent）、单纯缩放图片（原生「缩放图像」）、自由裁图（原生「裁切图像」更直观）——「图像规范」的裁切只用于对齐裁边。

## 安装

**方式一：ComfyUI Manager（推荐）**——在 Manager 的「安装自定义节点」里搜 `ComfyUI-xingz`，或用命令行：

```bash
comfy node install ComfyUI-xingz
```

已发布到 Comfy Registry：https://registry.comfy.org/nodes/ComfyUI-xingz

**方式二：git clone**

```bash
cd ComfyUI/custom_nodes
git clone https://github.com/yaggag7/ComfyUI-xingz.git ComfyUI-xingz
```

装完重启 ComfyUI，节点菜单里搜「图像信息」或「图像规范」。
（下载 zip 手动解压也行，但文件夹必须叫 `ComfyUI-xingz`。）

## 图像信息

输入 `图像`（IMAGE），输出：

| 输出 | 类型 | 说明 |
|---|---|---|
| 宽度 / 高度 | INT | 像素尺寸 |
| 宽高比 | COMBO | 最接近的标准画幅，取值与「分辨率选择器」下拉一致，如 `16:9 (Widescreen)` |
| 百万像素 | FLOAT | 宽×高÷1024²（与分辨率选择器同口径），上限 16 |
| 分辨率 | STRING | 如 `1920x1080`，可接文件名前缀、预览、文本拼接 |

**连「分辨率选择器」**：把「宽高比」拖到它的宽高比行、把「百万像素」拖到百万像素行（控件会自动变成输入口），倍数留默认，运行即按原图比例和原图像素量出尺寸。

> 百万像素按 1024×1024 = 1 MP 计，所以 1920×1080 显示 1.98 而不是 2.07——只有这个口径下游才能算回原尺寸。
>
> 宽高比是 COMBO 输出（不是字符串），因为 ComfyUI 前端只允许 COMBO 连进下拉框控件。

## 图像规范

输入 `图像`，参数：

| 参数 | 默认 | 说明 |
|---|---|---|
| 对齐倍数 | 16 | 目标宽高都取这个数的倍数 |
| 策略 | 最小像素改动 | 也可选：最小比例偏差 / 只放大 / 只缩小 |
| 处理方式 | 缩放 | 重采样整图；选「裁切」则居中裁掉多出的像素，不重采样 |
| 缩放算法 | lanczos | bicubic / bilinear / area / nearest-exact |

输出：`图像`、`宽度`、`高度`、`参考分辨率`（INT，可直接接「文本编码 Qwen 图像 2.1」的分辨率）。

> 参考分辨率是 Qwen 编码器的「面积等效边长」：编码器用 √(分辨率² × 宽高比) 反推参考图尺寸并强制 32 对齐。目标宽高都是 32 的倍数时完全一致；用 16 对齐会有 ±16 偏差（例如 600×899 → 592×896 → 728，编码器实际用 576×896）。

## 典型连线

- **按原图比例出图**：加载图像 → 图像信息 →（宽高比 / 百万像素）→ 分辨率选择器 → 空 Latent
- **只把尺寸改合法**：加载图像 → 图像规范（倍数 16 或 32）→ 宽度 / 高度 → 空 Latent
- **文件名带尺寸**：图像信息 → 分辨率 → 保存图像的 `filename_prefix`
- **Qwen 图生图**：图像规范 → 参考分辨率 → 文本编码 Qwen 图像 2.1 的分辨率

## 说明

- 只读节点，不修改图像数据；同一批次内尺寸一致，宽高按批次形状取。
- 节点类型名 `ImageAspectRatio` / `NormalizeImage` 固定不变，改名只动界面显示名，旧工作流不断线。
- 版本变更与旧工作流兼容性见 [CHANGELOG.md](CHANGELOG.md)。
