# xingz（ComfyUI 自定义节点）

读取图像的尺寸与比例信息，直接驱动原生「分辨率选择器」；另附「图像规范」（把图像改成对模型合法的倍数尺寸并直接输出）。纯 Python 实现，不依赖第三方库。

共 2 个节点：`图像信息`（读）、`图像规范`（做）。

## 安装

1. 整个 `xingz` 目录放进：

   `ComfyUI/custom_nodes/xingz`

2. 重启 ComfyUI（Desktop 版：菜单/托盘里的 Restart，或直接退出重开），刷新网页。

3. 节点菜单里搜索 `图像信息`、`图像规范`（旧名 `图像宽高比` / `规范化图像` 也可），或搜 `宽高比`、`比例`、`aspect`；分类在「图像/分析」下。

## 节点一：图像信息

输入：`图像`（IMAGE）

| 输出 | 类型 | 说明 |
|---|---|---|
| 宽度 | INT | 图像宽度（像素） |
| 高度 | INT | 图像高度（像素） |
| 宽高比 | COMBO | 最接近的标准画幅，取值与「分辨率选择器」下拉框完全一致，如 `16:9 (Widescreen)` |
| 百万像素 | FLOAT | 宽 × 高 ÷ 1024 ÷ 1024，与「分辨率选择器」同口径；上限夹到 16.0 |
| 分辨率 | STRING | 宽高拼成的一行文本，如 `1920x1080`；可接文件名（`SaveImage` 的 `filename_prefix`）、文本拼接、预览类节点 |

执行后会返回一行文本预览：`1920×1080 · 16:9 · 1.98 百万像素 → 分辨率选择器：16:9 (Widescreen)`（在节点输出/队列里可见）。

### 直接连「分辨率选择器」

「分辨率选择器」（ResolutionSelector）的 `宽高比` 和 `百万像素` 本来只是控件，接上本节点那一行就会变成输入口：

- 从本节点的 **宽高比** 拖线到「分辨率选择器」的 **宽高比** 那一行；
- 从 **百万像素** 拖线到 **百万像素** 那一行；
- 剩下的 **倍数**（默认 8）保持手填，点运行。

结果就是按原图比例、原图像素量还原一个可生成的尺寸。实测 1920×1080 → 分辨率选择器输出 1920×1080（倍数 8）；4000×6000 会先夹到 16 MP 再算。

> 百万像素用 1024×1024 作 1 MP 的基准（分辨率选择器内部就是 `megapixels × 1024 × 1024`），所以 1920×1080 显示 1.98 而不是 2.07——只有这个口径才能让下游算出原尺寸。

> 宽高比是 COMBO 类型输出（不是字符串）。这是 ComfyUI 前端唯一允许连进下拉框控件的类型，原生 `Convert String to Combo` 节点也是这么做的；普通 STRING 输出会被拦下。

## 节点二：图像规范

把任意尺寸的图改成「对模型合法」的倍数，并直接输出**改好的图片**，不用再挂缩放节点（这一步原来由单独的「尺寸规范」节点做，v2.9.0 已合并进来）。

输入：

- `图像`（必填）
- `对齐倍数`（默认 16）
- `策略`：`最小像素改动` / `最小比例偏差` / `只放大` / `只缩小`
- `处理方式`：
  - `缩放`（默认）：重采样到目标尺寸，构图完整不变形
  - `裁切`：居中裁掉多出来的几个像素，**不重采样、像素原样保留**（只能缩小；目标比原图大时自动退回缩放）
- `缩放算法`：`lanczos`（默认，质量最好）/ `bicubic` / `bilinear` / `area` / `nearest-exact`

输出：`图像`（IMAGE）、`宽度`、`高度`、`参考分辨率`（INT，对齐粒度跟随「对齐倍数」，接「文本编码 Qwen 图像 2.1」的「分辨率」）。

> 这个节点不再输出 `分辨率`（STRING 文本）：要拿尺寸文本做文件名/预览，用上游「图像信息」的 `分辨率`。要驱动「空 Latent 图像」请用 `宽度`/`高度`；要驱动「分辨率选择器」用「图像信息」节点的 `宽高比` + `百万像素`。

实测（600×899 的真实运行，落盘后核对 PNG）：缩放 → **592×896 RGB**；裁切 → **592×896 RGB**（与「图像信息」节点给出的 592/896 完全一致）。

### 连「文本编码 Qwen 图像 2.1」的分辨率

那个节点的「分辨率」是 INT（0~4096，步长 32），含义不是长边也不是像素总数，而是**参考图的面积等效边长**：它用 √(分辨率² × 宽高比) 算出参考图的宽高，并把两边强制 32 对齐。

「参考分辨率」这个输出就是按同一套公式反推出来的值，**对齐粒度跟随「对齐倍数」**（倍数填多少，就按多少去找最合适的值），直接拖到那个「分辨率」输入口即可（INT ↔ INT，实测连得上、能执行）：

| 目标尺寸（倍数） | 参考分辨率 | 编码器实际用的参考图尺寸 |
|---|---|---|
| 608×896（32） | 738 | 608×896（完全一致） |
| 1024×1536（32） | 1254 | 1024×1536（完全一致） |
| 592×896（16） | 728 | 576×896（宽 −16） |
| 608×912（16） | 745 | 608×928（高 +16） |

- 尺寸两边都是 32 的倍数时能完全复现；16 对齐时必然有 ±16 偏差（592、912 本身不是 32 的倍数，无解）。
- 「跟随倍数」改的是**取值假设**：值本身由面积 √(宽×高) 主导，实测 8 组尺寸 × 倍数 8/16/32/64 下，跟随倍数与写死 32 算出的值完全一致（600×899 规范成 600×896 / 592×896 / 608×896 时，参考分辨率分别是 733 / 728 / 738）。真正决定编码器行为的是它写死的 32，所以倍数不是 32 的整数倍时，节点文本会标注「按 N 对齐估算；Qwen 编码器固定 32 对齐」。
- 想完全一致，就把「对齐倍数」改成 **32**：600×899 + 倍数 32 → 608×896 → 参考分辨率 738 → 编码器正好 608×896。
- 编码器是把参考图缩到「约 738×738 的面积」，不是把图变成 738×738。

## 典型用法

- **按原图比例出图（推荐）**：加载图像 → 图像信息 →（宽高比、百万像素）→ 分辨率选择器 → 空 Latent 图像。
- **按指定比例出图**：分辨率选择器（宽高比下拉 + 百万像素 + 倍数）→ 空 Latent 图像，「按比例算尺寸」的活它已经干了。
- **不改构图、只把尺寸改合法（喂空 Latent）**：加载图像 → 图像规范（倍数 16，缩放，策略按需）→ 宽度/高度 → 空 Latent 图像。
- **要一张改好尺寸的成品图**：加载图像 → 图像规范（倍数 16，缩放或裁切）→ 保存图像 / 直接喂图生图。
- **生成后回到原尺寸**：空 Latent 用规范尺寸出图 → 缩放图像（Upscale Image，方法 lanczos）填回原图 600×899。
- **文件名带尺寸**：加载图像 → 图像信息 → `分辨率` 接「保存图像」的 `filename_prefix`，落盘就是 `1920x1080_00001_.png`。
- **筛选/分支**：用「宽高比」或「百万像素」接比较/逻辑节点做横竖图分桶、低分辨率分流。

## 备注

- 同一批 IMAGE 内各张尺寸一致，宽高取的是这批图像的形状。
- 节点只读不写，不改动图像数据。
- 需要 ComfyUI 0.39+（使用 V3 节点 API 的 `comfy_entrypoint` 注册，因为 COMBO 输出只有 V3 能声明）。节点类型名 `ImageAspectRatio` / `NormalizeImage`。
- v3.0.0 节点包改名为 `xingz`：目录名、pyproject 的 `name`、ComfyUI Manager 里的 `DisplayName` 都改为 `xingz`。节点类型名（`ImageAspectRatio` / `NormalizeImage`）与界面名（图像信息 / 图像规范）保持不变，旧工作流不受影响。升级时先删掉旧的 `comfyui-image-aspect-ratio` 目录，避免两个包同时注册同名节点。
- v2.9.0 删掉了「尺寸规范」（SizeNormalize）：它算尺寸的活和「图像规范」完全重叠（同一套策略与目标尺寸），「图像信息」+ 原生「分辨率选择器」/「缩放图像」也能覆盖；旧工作流里这个节点会显示丢失，需要改用「图像规范」或原生节点。
- v2.8.0 三个节点改名：`图像宽高比` → `图像信息`、`尺寸规范化` → `尺寸规范`、`规范化图像` → `图像规范`。节点类型名（`ImageAspectRatio` / `SizeNormalize` / `NormalizeImage`）不变，旧工作流不受影响；旧名字保留为搜索别名，所以搜旧名也能找到。
- v2.7.0 把 `分辨率`（STRING，如 `592x896`）从「图像规范」（原名「规范化图像」）挪到了「图像信息」（原名「图像宽高比」，第 5 个输出）；「图像规范」的输出从 5 个变 4 个，`参考分辨率` 的索引由 4 变 3，旧工作流里连到它的线会断，需要重连。「尺寸规范」（v2.9.0 已删除）的 `分辨率` 保留不动。
- v2.6.0「参考分辨率」的对齐粒度改为跟随「对齐倍数」（之前写死 32）；倍数不是 32 的整数倍时，执行文本会注明编码器实际仍按 32 对齐。取值本身几乎不变。
- v2.5.0 给「尺寸规范」（v2.9.0 已删除）、「图像规范」加了第 5 个输出「参考分辨率」（INT）：原来的「分辨率」是 STRING，前端不允许连到 INT 输入口（比如「文本编码 Qwen 图像 2.1」的分辨率），所以另开一个整数口。已有输出的索引没变，旧连线不受影响。
- v2.4.0 删掉了「按比例算尺寸」（AspectRatioSize）：它算尺寸的活和原生「分辨率选择器」（宽高比 + 百万像素 + 倍数）完全重叠，也和「尺寸规范」重叠。旧工作流里这个节点会显示丢失，把它替换成「分辨率选择器」或「图像规范」即可；需要回退就把 `backup/comfyui-image-aspect-ratio-v2.3.0\nodes.py` 拷回来。
- v2.0 起输出从 11 个精简为 4 个：旧工作流里连到「批次/比例宽/比例高/比例文本/方向/标准画幅/画幅偏差」的线会断，需要手动重连。
